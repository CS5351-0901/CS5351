# User stories from the configuration and skill contract

- As a user, I want `/agent` requests to be recognized only when addressed to the bot, so that ordinary messages do not start a coding task.
- As a user, I want my request reduced to core features, constraints, project type, and size, then shown in a structured proposal, so that I can confirm the intended work.
- As a user requesting a medium or large project, I want to review the proposed architecture and scaffold before implementation continues.
- As a user, I want task progress, completed steps, errors, and snapshots represented in `process.json`, so that an interrupted task can be considered for resumption.
- As an administrator, I want user and group blacklists, internet access controls, and knowledge-use controls, so that access and optional capabilities can be configured.
- As an operator, I want execution time, memory, file-size, debug-round, and quality thresholds to be configurable, so that resource use and iteration have explicit limits.
- As a user, I want the contract to define review and test steps for generated Python and JavaScript/TypeScript projects, so that quality expectations are visible before implementation.

## Change and reason

The existing `_save_snapshot` used whole seconds in the snapshot filename.
Two saves for the same session and step during the same second therefore used
one path and overwrote the earlier recovery point. A deterministic regression
freezes wall-clock seconds and supplies two distinct nanosecond timestamps.
Before the production change, the C1 suite ran 8 tests: 7 passed and this
regression failed because the two returned paths were identical.

`main.py::_save_snapshot` now uses `time.time_ns()` in the filename. The JSON
payload, directory structure, and rollback API are unchanged. This removes the
whole-second collision demonstrated by the test; it does not promise atomic
multi-process writes or uniqueness if the clock repeats the same nanosecond.

`tests/roles/c1/test_baseline.py` adds two executable regressions:

- Both same-second saves retain their original code and files in separate JSON
  snapshots; rollback selects the newer snapshot using explicit filesystem times.
- Newer snapshots from another step or session do not affect the requested
  recovery point.

Only the C1-owned helper, C1 tests, and C1 Week 6 evidence are changed. Existing
Week 1–5 evidence is retained. No Week 7–13 evidence is created.
